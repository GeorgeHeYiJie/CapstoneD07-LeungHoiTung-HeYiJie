# GPU训练要用的

这个文件夹可以单独下载，再上传到租来的 GPU 机器上训练高维矩阵模型。仓库根目录里的原文件还在原处，没有移动，也没有改内容。

这里训练的是 `HighDimensionMatrix-PINN_Combination.py`：用 Wu 等人的周期矩阵，同时训练 Wang 的 PINN 和 Zhang 的 SOH 模型。它不是 `训练要用的` 里的原始 17 维 PINN，也不是 `scripts/` 里那套 HD-SOH-v1 四组对比。那套对比脚本把网络留在 CPU 上，结果已经在 `results/high_dimension_comparison/`。

## 里面有什么

| 路径 | 作用 |
| --- | --- |
| `HighDimensionMatrix-PINN_Combination.py` | 训练脚本，与仓库根目录原文件字节相同 |
| `data/MIT data/` | 125 个电池 csv，按三个日期批次分文件夹 |
| `data/HUST data/` | 77 个电池 csv，直接放在这一层 |
| `requirements-gpu.txt` | numpy、pandas、scikit-learn、matplotlib |
| `开始训练.py` | 检查文件，并在确认后用 CUDA 启动训练 |
| `说明.md` | 本说明 |

不在这里的东西：XJTU、TJU、作者预训练权重、论文图、HD-SOH-v1 的九个分析脚本。这个训练入口不读取它们。

## 在 GPU 机器上安装

不要安装仓库根目录的 `requirements-reproduction.txt`。那个文件会装 CPU 版 PyTorch，GPU 不会参与计算。

先按显卡驱动安装 CUDA 版 PyTorch，再装其余依赖。CUDA 12.4 的例子：

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements-gpu.txt
python 开始训练.py --check
```

其他 CUDA 版本的安装索引见 https://pytorch.org/get-started/locally/ 。`--check` 会核对 125 个 MIT csv、77 个 HUST csv，以及脚本能否编译。它不会开始训练。

## 开始训练

在本目录执行：

```bash
python 开始训练.py --run MIT --yes
python 开始训练.py --run HUST --yes
```

两条命令各自是一次完整训练，不会连着跑。MIT 留出 `2018-04-12` 整批做测试；HUST 留出文件名组号 `10`。其余电池用 `train_test_split(..., test_size=0.2, random_state=420)` 分成训练和验证。这不是原始 PINN「电池编号能被 5 整除就做测试」的划分。

固定设置：最多 200 个 epoch，stride 1，batch size 512，seed 420，`--device cuda`。验证集 Wang 的 MSE 连续 21 个 epoch 没有下降就提前停止。日志、配置和 `best_wang_valid.pt` 写到 `运行输出/<数据集>_<留出组>_<时间>/`。这个目录不提交到 Git。文件夹名里的时间用的是 GPU 机器自己的时钟。

如果 PyTorch 看不到 CUDA，`--yes` 会停下来，不会改在 CPU 上跑完整实验。

## 结果怎么读

SOH 是「容量 / 1.1 Ah」的小数，例如 0.90 表示 90%。MAE 和 RMSE 用这个小数，MSE 是它的平方。MAPE 是相对真值的百分比；目标为 0 的点不计入 MAPE。

checkpoint 是验证集上 Wang `solution_u` 的 MSE 最低的那一轮。同一轮的 Zhang 权重也保存在这个文件里。测试发生在训练结束、重新加载该 checkpoint 之后。一次成功的短检查只说明程序能跑，不能当成论文精度。
