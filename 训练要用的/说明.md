# 训练要用的

这里是训练和运行 PINN4SOH 所需要的文件副本。仓库根目录里的原文件还在原处，没有移动，也没有改内容。

训练时 SOH 是「容量 / 标称容量」的小数，例如 0.90 表示 90%。MAE、RMSE 用这个小数；MSE 是它的平方。

## 每一层放什么

| 文件夹 | 作用 | 里面有什么 |
| --- | --- | --- |
| `01_环境依赖` | 安装运行环境 | `requirements-reproduction.txt` |
| `02_模型` | 网络结构 | `Model/Model.py` 是 PINN。`Compare_Models.py` 只给 MLP/CNN 对比实验用 |
| `03_读电池数据` | 读 csv、清洗、归一化、划分 | `dataloader/dataloader.py` |
| `04_训练工具` | 日志和指标 | `utils/util.py` |
| `05_训练和运行脚本` | 入口，再按任务分了三层 | 四个数据集从零训练、对比基线、用已有权重微调 |
| `06_四个数据集` | 训练数据 | 下面的 `data/` 保持作者脚本要找的文件夹名 |
| `07_直接运行和微调用的权重` | 已经训练好的权重 | 微调脚本要找 `pretrained model/model_*.pth` |

`06_四个数据集/data` 里面继续按数据集分层，MIT 和 TJU 再按批次分层。XJTU 和 HUST 的 csv 必须直接放在各自文件夹里。作者脚本用 `os.listdir` 在这一层找文件，再拆一层就读不到电池。

从零训练不读取第 7 层的权重。那 11 个 `.pth` 是给 `main_adaptation - fine-tuning.py` 加载后继续微调用的。`pretrained model` 里还有一些 `mu_var_pi_*.npz`，当前训练和运行代码没有引用，所以没有复制进来。

这些也不在这里：论文图、`plotter`、`results analysis`、历史复现脚本、PDF。它们不参与训练，也不参与加载这个模型做预测。

## 怎么训练

在本目录（`训练要用的`）下：

```bash
python 开始训练.py --check
python 开始训练.py --run XJTU --yes
```

`--run` 可以写成 `XJTU`、`HUST`、`MIT`、`TJU`、`comparison`、`finetune`。

`开始训练.py` 会做两件事，这样作者脚本不用改路径：

1. 把模型、数据读取、工具和入口脚本所在的目录加进 Python 路径。
2. 在 `运行输出/` 里接上 `data` 和 `pretrained model`，然后把工作目录切过去。日志和 `model.pth` 会写在 `运行输出/` 下面。

`运行输出/` 是训练产生的结果，不提交到 Git。

作者原来的 `main()` 一次会跑很多轮，不是只训一个模型：

- XJTU：6 个工况 × 10 次实验
- HUST：10 次实验
- MIT：10 次实验
- 对比基线：XJTU 上 MLP，6 个工况 × 10 次实验

每次最多 200 个 epoch，验证集连续约 20 个 epoch 没有提升会提前停。请确认时间和机器后再加 `--yes`。

`main_TJU.py` 和微调脚本的文件末尾是 `pass`。加上 `--run TJU --yes` 或 `--run finetune --yes` 会执行作者文件，但不会进入训练函数。

环境锁是按 Windows x86-64、Python 3.12 准备的。训练代码实际会导入的是 torch、numpy、pandas、scikit-learn。安装方式见仓库里的 `ENVIRONMENT.md`。
